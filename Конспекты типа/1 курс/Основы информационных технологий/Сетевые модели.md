### Введение
модель OSI - данная модель разделяет процесс на семь взаимосвязанных уровней, каждый из них выполняет свои функции и взаимодействует с уровнями ниже или выше.

| №   | Название                     | Задача                                                                  |
| --- | ---------------------------- | ----------------------------------------------------------------------- |
| 7   | Прикладной (Application)     | Доступ приложений пользователя к сети                                   |
| 6   | Представления (Presentation) | Кодирование, шифрование и сжатие данных.                                |
| 5   | Сеансовый (Session)          | Создание, поддержка и завершение сеанса связи                           |
| 4   | Транспортный (Transport)     | Обеспечение качества доставки данных между процессами, контроль ошибок. |
| 3   | Сетевой (Network)            | Логическая адресация и маршрутизация                                    |
| 2   | Канальный (Data Link)        | Физическая адресация (MAC), работа или передача внутри локальной сети   |
| 1   | Физический (Physical)        | Передача необработанных битов внутри физической среды.                  |
|     |                              |                                                                         |
Данная модель разрабатывалась еще с 1970-х для описания архитектуры и принципов работы сетей передачи данных. Является *эталонной* моделью.

#### Зачем она нужна?
- Совместимость оборудования.
- Устранение неисправностей - сетевые инженеры проверяют сеть пошагово (обычно снизу вверх).
- Разделение труда - программистам (например, разработчикам браузера) поручается работа с определенными уровнями.

### Принципы передачи данных
- Инкапсуляция (оправка) - движение данных сверху вниз. Каждый последующий уровень добавляет свой служебный заголовок.
- Декапсуляция - обратный процесс, последовательное чтение и удаление заголовков при движении данных от первого к седьмому или снизу вверх.
- Независимость уровней (модульность) - принцип, при котором каждый уровень выполняет трого свою задачу и взаимодействует только с двумя соседними уровнями.

### Почему TCP/IP лучше OSI
TCP/IP является практической реализацией, она проще и быстрее. Целью ее создания было решение конкретных задач передачи данных!

### Практический пример

#### Условие
![[Pasted image 20261111110340.png|356]]
Пользователь Максим Эдуардович совершает аудиозвонок через мессенджер Амск, со своего смартфона, подключенного по WiFi, своему студенту, Владу Кондратьеву. Голосовой пакет передается в реальном времени.

#### Задача
1. Описать путь одного голосового пакета от М.Э. до сети (отправки).
2. Описать процесс приёма голосового пакета В.К.

#### Решение задачи 1


| №   | Уровень | Что происходит? |
| --- | ------- | --------------- |
|     |         |                 |
 - Прикладной уровень: Приложение аМск записывает голос М.Э. Формируется поток данных реального времени.
 - Представительский уровень: Звук оцифровывается, сжимается и надежно шифруется.
 - Сеансовый уровень: Сигнальные протоколы поддерживают активную сессию звонка. Это последний уровень, в котором единица измерения - данные (Data).
 - Транспортный уровень: Используя протокол UDP
 - Физический уровень: Wi-Fi передатчик смартфона переводит кадр в последовательность битов и излучает их в эфир в виде радиоволн.

Выход в глобальную сеть: WiFi-роутер принимает сигнал, снимает заголовок WiFi, на 3-м уровне подменяет IP смартфона на внешний публичный IP (NAT), упаковывает пакет в проводной кадр Ethernet и отправляет в сеть!
